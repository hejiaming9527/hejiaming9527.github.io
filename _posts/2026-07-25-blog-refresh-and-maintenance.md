## 项目说明

这是一个持续维护中的个人 Web 项目。目标不是单纯更换皮肤，而是让博客同时承担两件事：一是面向 HR 和合作方清楚呈现教育、项目与可迁移能力；二是为后续技术学习、工作复盘和生活记录保留可持续更新的空间。

## 项目背景

原有博客的内容入口、项目说明和视觉表现不够统一：首页和栏目页的风格容易割裂，项目详情缺少统一的记录框架，深色环境下可读性较好但低亮度设备或浅色偏好下不够友好。改版以 Jekyll 静态站点为基础，在不引入复杂运行服务的前提下完成内容与界面的整理。

## 目标与范围

- 重新组织首页、分类、标签、归档、关于和电子简历的入口。
- 将课程设计明确标记为小组合作，只描述本人实际参与的部分。
- 为项目页统一“目的、背景、技术、困难、处理方式、功能、复盘”的记录结构。
- 保留中世纪羊皮纸的深色主题，同时提供阅读舒适的浅色主题。
- 让主题切换、导航、页脚和返回顶部控件在常用全屏与缩放尺寸下保持可用。
- 通过 GitHub Pages 发布，并在上线后检查实际页面而非只看本地效果。

## 技术方案

| 层级 | 方案 | 作用 |
| --- | --- | --- |
| 静态站点 | Jekyll + Chirpy | 生成文章、分类、标签、归档与基础交互 |
| 页面定制 | Liquid 模板 + HTML | 重构首页、侧边栏与简历入口 |
| 视觉系统 | SCSS、CSS 变量、渐变与透明度 | 建立深浅色主题与栏目撞色 |
| 主题状态 | `data-mode` + `sessionStorage` | 在当前会话中保存明暗主题选择 |
| 响应式检查 | 浏览器开发者工具与全屏/缩放测试 | 检查不同宽度下的对齐、溢出和可读性 |
| 发布 | Git + GitHub Pages | 版本管理与线上静态部署 |

## 实现功能

### 1. 信息架构与项目入口

首页按照时间从早到晚展示课程设计、个人学习实践和博客维护项目；每张项目卡片直接跳转到对应详情文章。分类页保留层级关系，标签页用于横向聚合技术、方法和记录类型，便于后续新增生活、工作复盘或学习笔记。

### 2. 深浅色主题切换

主题开关不再额外占用头像下方的空间：**点击侧边栏头像即可切换深浅色**。切换时通过局部波纹反馈状态变化；深色模式使用黑曜石、暗金和低饱和青绿，浅色模式转为纸张、米白与棕金，在保持同一气质的同时提升低亮度环境的阅读清晰度。

### 3. 栏目撞色与阅读层次

首页保持克制的统一色调；分类、标签、归档、关于、电子简历等栏目则使用不同但饱和度受控的强调色。鼠标悬停导航时出现边框和微光变化，帮助确认当前位置，同时避免持续动画造成干扰。

### 4. 可维护内容模板

项目文章均以明确的小节记录背景、目标、本人参与、技术方案、实现功能、困难处理和工作日志。后续发布新的学习或工作记录时，可沿用这一结构，减少遗漏关键信息的情况。

## 遇到的困难与处理方法

### 主题切换控件破坏头像对齐

最初将主题按钮放在头像旁或头像下方，虽然功能可用，但在全屏与缩放状态下容易显得突兀，也会打破侧边栏的视觉重心。后来改为将头像本身作为按钮：头像尺寸和位置不变，点击区域覆盖头像内容，波纹仅在头像圆形区域内出现。

### 深色样式覆盖浅色页面

原有样式中部分深色选择器优先级较高，切换浅色后会出现“深色卡片配深色文字”或页脚颜色残留。处理方式是为标准栏目页、首页组件、简历组件和页脚分别补充浅色覆盖规则，同时降低背景纹理和阴影透明度，保证文字与背景保持足够对比。

### 不同尺寸下的细节错位

圆形返回顶部按钮、头像和技能卡片在浏览器全屏、页面缩放或较窄窗口中可能出现图标偏移、文字溢出或横向滚动。通过固定关键控件的盒模型、使用 Grid 的 `minmax(0, 1fr)`、为移动端设置单列布局，并以实际浏览器尺寸复查，避免只在单一截图下“看起来正常”。

### 线上部署与本地结果不一致

静态站点发布有构建和缓存时间，代码提交后不能只以本地预览为准。每次更新后检查 GitHub Pages 返回的 HTML、样式资源和实际页面状态；若发现旧资源仍在缓存，先确认部署提交与页面更新时间，再进行强制刷新或等待 CDN 更新。

## 阶段性工作日志

> 以下记录对应本次博客维护的实际改版步骤，后续会在持续维护中补充新的提交和验证结果。

1. **内容盘点：**整理简历、课程项目、制造现场改善训练与学习实践，区分小组合作、个人学习与工作经历。
2. **页面重构：**调整首页叙事、项目卡片、关于页技能区和电子简历入口，建立按时间排序的项目展示。
3. **主题设计：**确定深色羊皮纸与浅色纸张两套基础色，分别处理侧边栏、内容卡片、栏目强调色和页脚。
4. **交互修正：**将主题切换从独立按钮收回到头像点击区域，添加局部波纹反馈并保留键盘可访问性。
5. **响应式核对：**在全屏、常用缩放比例和窄窗口下检查头像、返回顶部、技能卡片、页脚与导航的对齐情况。
6. **部署验收：**提交 Git 变更、推送至 GitHub，并在线上页面确认 HTML 已更新、主题入口可见、分类和项目链接可访问。

## 项目复盘

这次改版让我更直观地理解了“界面完成”与“可交付”的差别：视觉稿只能说明方向，真正需要验证的是信息是否准确、不同设备是否可读、交互是否自然，以及上线后的资源是否真的生效。后续会继续保持小步提交：新增内容时同步补齐标签、分类、项目上下文和验证记录，让博客本身成为持续积累的工程作品。
