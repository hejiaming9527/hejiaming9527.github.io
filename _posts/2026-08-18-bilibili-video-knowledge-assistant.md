项目源于“网页数据抓取与可视化实践”：原来只完成公开页面请求、HTML 解析、字段清洗和统计图表；后来我发现，收藏的视频真正缺少的是可检索、可核对、能持续积累的知识结构。因此把它改造成一个本地桌面助手，将用户主动提交的 B 站公开视频链接整理为摘要、分类、标签、完整转录、术语卡和可审阅关系。

## 处理流程

1. 清洗链接并提取稳定 BV 号。
2. 使用 `yt-dlp` 读取元数据、字幕和音频信息。
3. 优先采用站内字幕；没有字幕时使用 faster-whisper 或可选 FunASR 进行本地转录。
4. 根据用户选择调用本地或云端 Provider，输出结构化摘要、分类、标签、专业视角与待核验项。
5. 生成本地 Markdown 笔记，并用 SQLite 保存任务状态、失败分类和审计信息。
6. 从已确认术语生成证据回链、关系候选和本地图谱；所有合并、排除与关系确认均由用户决定。

### 产品运行时 AI

Ollama、DeepSeek、Kimi、硅基流动属于软件提供给用户选择的内容分析 Provider。它们负责在明确选择后分析转录文本，但不是“项目由这些模型自动完成”的证据。没有配置 Key 时会跳过云端 Provider；测试不会伪造付费 API 调用成功。

## 关键难点

### 转录质量不能只看“生成成功”

专有名词和低置信片段即使能输出文字，也可能误导后续摘要。我保留原始时间戳，允许人工纠错，使用次模型只标记低相似片段，并记录人工文本与原始文本的关系，而不是直接覆盖证据。

### AI 术语关系不能自由联想

关系候选只来自人工确认的别名，或两个已确认术语共同出现于同一来源视频。候选必须说明依据，由用户确认或忽略；只有确认后的边才会进入交互式图谱。

### 错误日志也要保护隐私

失败历史只公开结构化阶段、错误码和可安全展示的提示，不直接返回原始异常文本。旧数据库通过兼容迁移补充失败字段，保留原记录且不把未知错误猜成确定原因。

## 验证与限制

本轮重新运行 46 项 Python `unittest` 离线回归，全部通过；Vue 3 / TypeScript 类型检查、Electron 主进程/预加载/渲染端生产构建通过。项目只处理用户主动提交且有权用于个人学习的公开视频，不读取完整收藏夹，不绕过登录、会员、验证码或 DRM，也不建议公开传播音视频和完整转录。

这个演进过程让我把“抓到数据”升级为“形成可信知识”：数据有来源、模型有边界、人工有最终决定权、失败也能被审计和复盘。
